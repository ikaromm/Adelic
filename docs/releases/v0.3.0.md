# Adelic v0.3.0

2026-10-06 — Linux x86_64, aplicativo local em 127.0.0.1.

Esta versão traz uma interface nova e uma memória que funciona também com o ai-memory em Docker.

**Interface.** Tema escuro inspirado no Dracula, um pouco mais escuro, com layout baseado no T3 Code.
- Barra lateral: conversas recentes com tempo relativo.
- Mensagens: as suas em bolha; a atividade do turno aparece compacta ("Trabalhou por …").
- Campo de mensagem: modelo, thinking, permissões e projeto/modo ficam em botões arredondados.
- Menus: abrem colados ao botão.
- Rolagem: só acompanha o fim quando você já está lá.
- Botões de copiar em mensagens e blocos de código.
- Fontes Inter e JetBrains Mono incluídas no aplicativo; nenhum texto visível abaixo de 11 px.
- [Tema e interface](../specs/visual-theme.md).

**Logo.** Uma árvore 2-ádica em forma de "A", atravessada pela reta real. São as duas metades que o anel de adeles une; a mesma figura lembra um coordenador delegando a executores. Usada no ícone, no favicon e na barra lateral.

**Memória.** A biblioteca usa somente a API do ai-memory, sem ler o SQLite nem os arquivos Markdown do serviço. Por isso funciona com o serviço instalado no computador e em Docker (volume `ai-memory-data`).
- Configuração: `ADELIC_MEMORY_URL` (só loopback), mais `ADELIC_MEMORY_TOKEN` ou `ADELIC_MEMORY_TOKEN_FILE` quando o serviço usa `AI_MEMORY_AUTH_TOKEN`.
- Edição: passa pelo writer do próprio serviço, preservando os metadados. Notas cujos metadados nenhum writer consegue reproduzir ficam somente leitura.
- Erros de serviço indisponível, token ou API ausente aparecem na tela em vez de um catálogo vazio.
- [Contrato e limites](../specs/shared-memory.md).

**Kiro.** A disponibilidade depende só da verificação `Auth` do `kiro-cli doctor --all`. Falhas de integração do terminal não marcam mais um Kiro autenticado como indisponível.

**Desenvolvimento.** Integração contínua no GitHub Actions: typecheck, testes com bubblewrap real e build. Testes que dependiam de temporização, da pasta temporária ou de `/home` foram corrigidos.

Dependências, limites de execução e a política de aprovações não mudaram desde a [v0.2.0](v0.2.0.md). Compatibilidade comprovada: Arch/Omarchy x86_64 com Wayland.
